# M6B baseline audit

- `include/robot_sim/simulation.hpp` and `src/simulation.cpp` own robot IDs, VM lifetime, fixed tick time, CPU budgets, worker scheduling and safe-point inspection. `Simulation::step(WorldInput)` is synchronous. `Vm::run` executes one VM on one worker. `Bus` owns RAM, controller registers, power, RTC and latched interrupts. The coordinator processes RTC alarms in deadline/robot order.
- At tick entry, `Simulation` validates replies by robot and local request sequence, commits replies, handles timeouts and raises pending IRQs. Workers execute next. The coordinator extracts at most one request per controller per tick in robot order, advances RTC and computes a state checksum.
- M6A uses `Bus::store` at offsets 0x120/0x124/0x128, `Bus::take_request` and `Bus::complete`. It accepts nonempty RAM ranges within committed memory and the configured limit. TX copies from RAM at extraction. RX copies owned reply bytes into RAM before status and IRQ bit 2. Busy access has ordinary checked RAM semantics. `tests/core.cpp` covers TX, bounds, IRQ wake, RX delivery and matching checksums on 1/2/4 workers. The CLI text trace serializes reply bytes and IRQ inputs. There is no save-state format for in-flight transfers.
- The baseline accepts only the abstract protocol. Each VM carries its own pair of controller/device pins and address. There is no registered external device identity, shared-device arbitration, device bandwidth or separate readiness gate. Raw IRQ input is an existing trusted CLI/library interface. Guest MMIO has no reset/cancel register. Zero-length DMA faults under the existing ABI.
- CLI commands are `validate`, `run`, `profile` and `test`. The version-1 robot JSON covers CPU rates, RAM pages, connection pins, target, timeout and DMA limit. Scenario JSON covers ticks/rate, seed, workers, IRQs and final assertions. `tests/cli_replay.cmake` verifies recorded replies, checksum replay and failed assertions.
- M6B needs a coordinator-facing adapter for registration, connection, normalized requests, response readiness, device events, global IDs and cancellation. It can translate terminal results to `WorldInput` and reuse `Simulation::step` and M6A's existing completion path. Legacy CLI and raw library interfaces remain independently usable.
